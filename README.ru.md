# cursor-bridge

**MCP-сервер, который превращает headless `cursor-agent` от Cursor в дисциплинированную вторую AI-рабочую силу для Claude Code** — делегируйте механическую работу, запускайте многоосевые адверсариальные ревью и проверяйте находки парой «прокурор/адвокат». Каждая задача работает под watchdog'ами, git-предохранителями и локальной телеметрией.

🇬🇧 [English version](README.md)

---

## Зачем

Если вы платите и за Claude Code, и за Cursor — квота Cursor часто простаивает, пока Claude делает всё сам. cursor-bridge ставит её в строй:

- **Ваши артефакты ревьюит другое семейство моделей.** Кросс-модельное ревью ловит то, что одномодельное штампует «одобрено».
- **Механика идёт параллельно.** Массовые правки, кодмоды, бойлерплейт, каркасы тестов — Composer пашет, пока Claude проектирует.
- **Машинно проверяемая верификация.** Находки ревью — гипотезы; пара опровергателей подтверждает или опровергает каждую по реальному коду, с цитатами, которые сервер сверяет дословно.

## Три механизма

### 1. Делегирование — `cursor_run` / `cursor_ask` / `cursor_reply`

Асинхронные задачи по любому репозиторию: режим `edit` (пишет код; гейт на чистое git-дерево или изоляция в worktree), режимы `plan` и `ask` (только чтение). Многоходовость: `cursor_reply` продолжает тот же чат Composer'а. До 3 параллельных агентов; модель переопределяется на каждый вызов.

### 2. Сыщики — `cursor_review` (многоосевое адверсариальное ревью)

Ревью **никогда не бывает одноосевым**: 2–3 параллельных ревьюера с намеренно разными характерами читают один артефакт и не видят друг друга.

| Набор осей | Оси | Для чего |
|---|---|---|
| `plan` (дефолт) | broad · strict · hygiene | спеки, планы, дизайн-документы |
| `code` | correctness · security · tests | исходный код (всегда все 3) |

Находки возвращаются структурированной таблицей (маркер / файл:строка / заголовок по осям) плюс сырые ответы и отчёт о пересечениях между осями. Машинный критерий чистого прохода: `completed && !parse_degraded && blockers_total == 0`.

### 3. Следователи — `cursor_refute` (проверка парой «прокурор/адвокат»)

На вход — папка находок (1–12 по одному участку кода). Параллельно работают две противоположные роли:

- **прокурор** — доказывает, что баг настоящий: прослеживает цепочку вызовов до поломки;
- **адвокат** — доказывает, что ложный: ищет защиты и задокументированные проектные решения.

Затем сервер применяет намеренно асимметричный свод:

| Исход | Условие |
|---|---|
| `confirmed` (авто) | обе роли CONFIRMED, обе цитаты прошли машинную проверку |
| `refuted` (авто-закрытие; **запись сохраняется, никогда не удаляется**) | обе роли REFUTED, обе цитаты прошли машинную проверку |
| `escalate` → человеку | всё остальное: спор, неуверенность, провал цитаты, отсутствие вердикта, деградация роли, изменившееся дерево |

«Машинная проверка цитаты» — буквальная: процитированный фрагмент обязан существовать в указанном файле **в пределах ±20 строк от указанной строки**, быть содержательным (не забором из `////`), лежать в git-tracked файле и сопровождаться собственным рассуждением. Состояние дерева пинуется между запуском и результатом (git HEAD + проверка чистоты); незапиненное дерево гасит все авто-вердикты. Упавшая или ленивая роль (проигнорировано >50 % папки) гасит все авто-закрытия по папке.

**Философия:** мост автоматизирует *труд* верификации, но никогда — *право* финального вердикта. Спорное всегда доходит до человека.

## Справочник инструментов

| Группа | Инструменты |
|---|---|
| Делегирование | `cursor_run`, `cursor_ask`, `cursor_reply` |
| Ревью | `cursor_review`, `cursor_review_result` |
| Верификация | `cursor_refute`, `cursor_refute_result` |
| Управление задачами | `cursor_status`, `cursor_result`, `cursor_jobs`, `cursor_cancel`, `cursor_stats`, `cursor_mark_analyzed` |

Каждый результат несёт `verify_note`: выдача субагента — непроверенное утверждение, пока не подтверждена по коду.

## Требования

- **Node.js ≥ 26** (сервер исполняет TypeScript нативно — без сборки)
- **[cursor-agent CLI](https://cursor.com/cli)** установлен и залогинен (`cursor-agent login`), активная подписка Cursor
- **Claude Code** (или любой MCP-клиент, умеющий stdio-серверы)

## Установка

```bash
git clone https://github.com/<you>/cursor-bridge.git
cd cursor-bridge
./install.sh            # сервер + скилл для Claude Code
# ./install.sh --no-skill
# ./install.sh --uninstall
```

Установщик регистрирует сервер через `claude mcp add --scope user` и кладёт опциональный **скилл cursor-delegate** в `~/.claude/skills/` — скилл учит Claude, *когда* браться за какой механизм. Для других MCP-клиентов зарегистрируйте stdio-сервер с командой `node <repo>/src/server.ts`.

После установки откройте **новую** сессию Claude Code — работающие сессии держат старый набор инструментов.

## Использование

Говорите с Claude естественно — скилл сам выберет инструмент:

```text
» Отдай в Composer: добавь JSDoc всем экспортируемым функциям в src/.
    → cursor_run(mode=edit) … cursor_result

» Второе мнение по docs/design.md.
    → cursor_review(artifacts=[…], axis_set=plan) … cursor_review_result

» Перепроверь эти пять находок по коду.
    → cursor_refute(findings=[…], cwd=…) … cursor_refute_result
```

Или вызывайте инструменты напрямую — например, папку на верификацию:

```jsonc
// cursor_refute
{
  "findings": [{
    "id": "B-001",
    "title": "бонус списан, а обновление заказа может упасть",
    "file": "src/pay.ts", "line": 42, "severity": "S1",
    "claim": "spendBonus проходит, затем updateOrders бросает — деньги списаны, скидка не записана"
  }],
  "cwd": "/абсолютный/путь/к/репо",
  "context": "модуль платежей; запиненный read-only worktree",
  "domain": "orchestration"   // кормит калибровку ложных опровержений
}
```

## Надёжность и безопасность

- **Три бюджета watchdog'а** на задачу: жёсткий таймаут, грейс до первого токена (думание — не зависание), межтокенный idle. Известный баг зависания `cursor-agent -p` обезврежен конструкцией.
- **Git-предохранители:** правки in-place требуют чистого дерева; `isolation: "worktree"` даёт рискованным задачам собственный git worktree.
- **Read-only значит read-only:** ревью и верификация работают в режиме `ask` — ваши файлы им недоступны на запись.
- **Данные только локально:** журналы задач и телеметрия живут в `jobs/` и `logs/` внутри репозитория (в gitignore). С машины ничего не уходит, кроме промптов, которые сам `cursor-agent` шлёт в API Cursor.
- **Промпты видны в локальном `ps`** — никогда не кладите секреты в брифы.

## Структура проекта

```text
src/            сервер, менеджер задач, watchdog'и, git-предохранители, движки ревью и верификации, телеметрия
skills/         скилл cursor-delegate для Claude Code (когда какой механизм)
tools/audit/    автономные помощники картирования репо (build-blocks, preflight) для масштабных аудитов кода
test/           285 тестов (node:test), включая e2e-обвязку с fake-agent
```
